- 状态：已修复并纳入 2026-09-28 冻结

## 整改清单

| 原问题 | 现象与修改要求 | 实施和验收边界 |
| --- | --- | --- |
| 7.1 同名替换 | 新版上传后旧片段不得参与检索；保存失败不能破坏原知识库 | 按文档身份替换旧 Chunk；事务写快照，失败保留原 generation；相同内容重复跳过 |
| 7.2 引用与拒答优先级 | 引用无效不能返回正常回答；明确拒答不能被“是否记载”规则覆盖 | 无效引用阻止回答，明确拒答优先；无证据拒答且无引用；来源支持的否定事实可正常回答 |
| 7.3 模型与索引一致性 | 不同模型或维度不得复用向量 | 快照记录 provider、模型身份及维度；缺身份的旧快照从 Chunk 重建，保留旧 generation |
| 7.4 真实样本验收 | 固定正交向量回归不能冒充语义检索结果 | 使用真实 Embedding/Chat，最终 15 道有答案、4 道无答案；同时核对事实、引用与拒答 |
| 7.5 上传提示 | 客户不能区分首次、重复和更新上传 | API/UI 返回并展示入库、跳过、替换三种状态 |
| 7.6 否定事实 | “未列出金额”不应一概拒答，也不能编造具体金额 | 存在性问法支持“有写/写明”等表述；有来源的未列出事实可回答；询问缺失具体值应拒答；混合问法只答已记载范围 |
| 7.7 完整向量空间身份 | 同模型名不同端点、同目录权重变更仍可能错误复用 | 规范化远程端点且不保存凭据；本地模型以完整内容 SHA-256 校验，不能只看路径或别名 |
| 7.8 质量评分 | 关键词命中掩盖错误数字、否定反转、额外断言或错引 | 全部事实、来源映射和原文支持同时核验；未知说法进入人工复核，阻止自动通过；见[共用标准](../../评测数据/评测标准.md) |
| 7.9 Top-K 一致性 | `top_k=1` 曾实际给出 6 个片段 | 内部候选可扩展到 K+5，但交给模型及最终返回均不得超过 K；API 1—20、UI 1—10；回归覆盖 K=1/5/20 |

## 必须保留的判定场景

- “十四小时”不能匹配“四小时”；数值及单位按完整边界核对，后续 V0.2 又补齐小数和负号。
- 同句“最长四小时且可永久借用”的额外说法须单独检查，不能因前半句正确自动通过。
- 明确拒答文本即使同时出现“资料未列出”和引用编号，也不能标成正常回答；无答案通过要求拒答状态、文本和零引用一致。
- “文档是否写了费用”与“费用是多少”分别判断；只有原文支持的“未列出”才能带来源回答。
- 扩大存在性候选时保留同主题的否定证据，最终仍遵守 Top-K；第 6 名以后的证据不计入 Top-5。
- 保存失败、同名更新、重复上传、远程端点变化、本地权重变化、旧快照重建均需要保护索引一致性。
