### 第二阶段：文档管理与前端改版（已实现）

制定时的理由：用户可以上传、更新和提问，但缺少查看知识库内容及删除旧资料的操作。目前已补齐文档列表、删除和资料库界面，实现情况见下方记录。

| 建议能力 | 修改要求 |
| --- | --- |
| 文档列表 | 从当前快照元数据展示文件名、文档标识、片段数量；说明应用保留 Chunk 和向量，不保存上传原文件 |
| 文档删除 | 通过文档标识删除对应文本、向量及稀疏检索内容；沿用快照事务，失败保留原 generation |
| 界面管理入口 | 支持查看已入库文档和确认删除，操作成功后更新列表及问答状态 |
| 重启与边界 | 删除结果重启后保持；删除最后一份文档、未知标识和保存失败均有清晰结果 |

2026-10-04 用户确认同时实现文档列表、删除接口，并要求本轮修改要求直接并入 005。本轮不另建公开规划文件，实施进展更新在本文件；原发布过程和证据保留。

#### 前端修改要求

- 使用 `interface-design` 与 `ui-ux-pro-max`，沿用 Streamlit，采用暖白纸面、墨绿强调色和清楚的中文层级。
- 导航提供“知识问答”和“资料库”；服务地址放入折叠设置，连接状态明确显示。
- 问答主区突出输入和答案，来源编号、文件名、PDF 页码及原文与答案对应；检索原始分和候选排名放入高级详情。
- 将 Top-K 表达为“参考片段上限”，保留默认 5 和中文说明，不展示为难以理解的主流程术语。
- 资料库提供上传、名称搜索、格式筛选、列表和删除确认；统计来自当前服务快照，不能使用虚构计数。
- 上传成功、重复跳过、同名替换、删除成功、加载、空知识库、连接失败均有明确反馈。资料改变后清除旧问答，避免继续展示过期来源。
- 使用原生可操作控件，提供焦点、禁用、忙碌和错误状态；窄屏可纵向阅读，按钮和文件名不挤压内容。

#### 接口修改要求

- `GET /documents`：返回当前 generation、文档和片段总数，以及每个文档的标识、文件名、片段数、已索引页数。
- `DELETE /documents/{document_id}`：删除指定标识的当前文档，返回剩余数量及新 generation；未知标识返回 404。
- 删除使用独立候选快照，磁盘保存成功后切换内存和稀疏表；保存失败保留原索引和 CURRENT。
- 支持删除最后一份文档并保存空快照，重启后知识库保持为空；再次上传可正常使用。
- 删除表示从当前可检索知识库移除；既有历史快照按恢复策略保留，界面不将此操作描述为彻底擦除所有历史文件。
