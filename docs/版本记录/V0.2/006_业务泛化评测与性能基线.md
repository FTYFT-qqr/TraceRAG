## 修改要求

### 1. 准备独立业务资料与题集

- 选择至少三份未参与既有调参的资料，覆盖 TXT、Markdown 和含文本层的 PDF；业务领域及具体资料在执行前确定。
- 建议最终验收集为 50 题：40 题有答案、10 题无答案。另设小规模开发集用于参数选择，不用最终验收题调参。
- 覆盖直接事实、数字与单位、否定与例外条件、术语改写、相近名称干扰、多个条件分散在同一资料不同片段、资料未提供的信息。多条件题要求覆盖全部预期事实。
- 每题保存唯一编号、问题、可回答性、预期来源、预期证据原文、预期事实及拒答要求；PDF 同时记录证据页码。
- 冻结语料和题集指纹；发现题集标注错误时保存修订版本及理由，不通过删除困难题或放宽预期事实消除失败。
- 新语料、题集使用独立目录，例如 `samples/business/006/`；既有 `samples/acceptance/` 和历史结果保持可追溯。

### 2. 扩展评测入口与报告

- 增加 `--corpus-dir`，让文档加载、来源校验和输入指纹统一使用指定目录，默认行为保持兼容。
- 通过正式 Loader 加载 PDF、Markdown、TXT，校验证据存在及页码对应；重复文件名、缺失来源和无可用文本需明确报错。
- 复用既有质量判定。新题集需要的标签与 PDF 来源定位按实际情况补齐，不降低事实、引用或拒答门槛。
- 质量对照采用各策略独立运行，或显式增加质量运行范围选项；每份报告明确哪些策略实际执行了 Chat，哪些只有检索结果。
- 每次输出写到新的批次目录，如 `docs/评测数据/版本0.2/业务泛化_日期_批次/`；保存逐题 JSON、配置、代码与输入指纹，以及人工复核判定。

### 3. 建立质量与性能基线

- 在同一输入、Embedding、切分配置和参考片段上限下，对照 vector、BM25、hybrid；先检索，再对需要比较的策略分别执行完整质量评测。
- 保留原有 50 题作为独立历史基线；新旧题集分开报告，不能混合计算或直接比较不同输入的准确率。
- 分别记录模型加载、文档解析/切分、向量化、建索引、单题检索、Chat 调用和总耗时。初始化与首题单列，常态耗时给出 P50/P95 和样本数。
- 记录进程内存、实际可获得的显存、模型请求次数、失败及重试、服务返回的 token 用量。无法取得的指标标记未采集，不估成零；离线批量检索耗时不冒充在线单题延迟。
- 在明确硬件、运行方式和工作负载前不预设延迟通过线。本轮先形成单用户基线，不扩展并发压测。

### 4. 根据失败原因选择优化

| 观测结果 | 优先分析与后续方向 |
| --- | --- |
| 证据没有进入候选集 | 检查解析遗漏、切分截断、术语匹配和召回配置；必要时再比较 Embedding |
| 证据已召回但排在前五之后 | 分析排名与干扰片段，评估 Reranker 对照 |
| 证据入选但回答遗漏条件、引用不支持或拒答错误 | 分析证据选择、回答协议和质量判定，不把问题全部归因于模型 |
| PDF 无文本或结构信息丢失 | 区分扫描件与复杂表格，再决定 OCR 或解析扩展 |
| 质量可用但运行耗时较高 | 根据分阶段数据分析加载、推理、批次及重复计算 |

优化只对开发集执行，每轮尽量改变一个因素，保存修改前后结果。最终验收集用于冻结后的验收；若验收暴露问题并触发整改，应记录其已参与反馈，后续再补充新的独立样本。

## 验收方式

| 项目 | 完成条件 |
| --- | --- |
| 语料与题集 | 新资料、新题集、原文证据及指纹齐全；开发集与最终验收集分离；PDF 页码可核对 |
| 评测入口 | 指定语料目录的加载、校验和指纹一致；默认旧样本行为兼容；报告能区分检索与真实回答质量 |
| 有答案质量 | 正常作答，全部预期事实匹配，引用可追溯且原文支持答案；数字错误、否定反转、引用不匹配均失败 |
| 额外说法 | 无法自动核实则待人工复核，不能自动通过；保留逐题判定依据 |
| 无答案质量 | 正确拒答且没有引用，回答内容与拒答状态一致 |
| 整体通过 | 沿用用户门槛：至少 10 条有答案问题的预期证据进入实际 Top-5，且每题质量通过、无执行错误、无未完成复核 |
| 性能基线 | 硬件、配置、样本数、分阶段耗时、P50/P95、内存和模型调用情况可追溯；未采集项明确标识 |
| 优化决策 | 每个问题有题目编号、相关片段及分类；明确下一轮优先方向与证据，不预先宣称需要新模型或新组件 |

完成评测并保存真实失败结果，也属于本轮可交付成果；质量未达门槛时必须标记未通过，并另列整改，不能为结束规划而改写判定。

## 结果与证据

### 输入与实现

- 新增三份[原创模拟业务资料及说明](../../../samples/business/006_数据说明.md)：订单服务 TXT、冷链交接 Markdown、三页文字层能源规则 PDF。正式 Loader 提取、原文与 PDF 页码校验均通过。另有 12 题开发集，与 50 道验收题（40 道有答案、10 道无答案）分离。
- 首版验收题集 SHA-256 为 `40bd3f4f02b4026cc8fbcbde98d7be2e11eaf42481de546eecfdef51d1e27b6e`。`B006-A1-17` 的问句含无原文依据的前提；按[题集修订记录](../../../samples/business/题集修订记录.md)保存 v1、只改问句的 v2 与两版指纹。最终整套重新运行的 v2 SHA-256 为 `04e9e4b3bebb0f680e34938c01da915522e74f29fbd758c716cad85f689b9e00`。语料与开发题集未因修订改变。
- `scripts/evaluate_v02.py` 增加 `--corpus-dir`、数据集模式和质量范围选项，复用正式 Loader，检查证据和 PDF 页码；默认历史 50 题行为保留。每次报告记录输入与关键代码指纹、配置及实际 Chat 执行范围。`scripts/evaluation_performance.py` 负责分阶段性能和资源记录；`scripts/aggregate_v02_runs.py` 核对三策略输入、代码、Embedding、切分与真实质量执行情况后生成统一对照。
- 数字质量判定修复了负数及带单位数值被拆出伪“额外数字”的误报，保留数字错答的失败判定。相应回归覆盖负温度、功率单位和真正的错误数字。

### 性能与资源基线

运行环境为 Windows 11 Pro 10.0.26200、Ryzen 7 5800H（8 核/16 线程）、约 16 GiB 内存、RTX 3070 Laptop 8 GiB；本次本地 Python/PyTorch CPU 运行，CUDA 不可用。工作负载为新三份资料、50 道完整质量题和独立的 50 次在线单题 Top-5 检索探针；未做并发压测。下面的常态 P50/P95 排除首题，样本数均为 49；单题检索探针与质量评估的预计算排名分别计时。

| 策略 | 总耗时 | 初始化 | 本地模型加载 | 单题检索常态 P50/P95 | Chat 常态 P50/P95 | 峰值进程 RSS |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| BM25 | 71.332 秒 | 1.098 秒 | 不适用 | 0.023/0.030 毫秒 | 1.303/1.870 秒 | 115.2 MiB |
| 纯向量 | 106.383 秒 | 19.309 秒 | 13.116 秒 | 167.049/182.748 毫秒 | 1.339/2.400 秒 | 2017.2 MiB |
