# 001 评测基线与检索优化规划

## 1. 轮次信息

- 版本：V0.2
- 状态：本轮验收通过，完成实现冻结（2026-10-03 BM25与混合召回均43/43质量通过、7/7拒答；工程发布后续进行）
- 日期：2026-09-28
- 前置版本：V0.1 已完成冻结

## 2. 目标

建立可重复的完整评测基线，再针对检索问题区分切分逻辑、Embedding 和召回策略的影响，避免在没有对照数据时直接改动生产链路。

## 3. 第一阶段：扩展评测集

建立约 50 条问题，至少包含：

- 有明确答案的问题；
- 有证据支持的否定事实；
- 文档未提供答案的问题；
- 数字、时间、范围和否定含义容易出错的问题；
- 需要多 Chunk 或跨页证据的问题；
- 同义问法和中英文混合问法。

每题固定记录：问题、是否可回答、预期事实、预期证据、预期来源、是否允许引用、拒答预期和人工复核条件。

## 4. 第二阶段：固定当前方案并生成基线

先冻结当前 Chunk 参数、Embedding 模型、索引和 Prompt，记录：

- 预期证据 Top-1、Top-3、Top-5 命中率；
- 回答事实匹配率；
- 引用可追溯率与引用原文支持率；
- 正确拒答率；
- 待人工复核数量；
- 失败问题及其完整检索排名。

基线报告必须保存逐题结果，不能只保存汇总数字。

## 5. 第三阶段：定位语义检索问题来源

按单变量原则进行对照：

1. 固定 Embedding 和检索参数，只比较不同切分长度、overlap 和边界策略；
2. 固定切分结果，只比较不同 Embedding 模型或模型配置；
3. 在当前向量检索基线之上加入 BM25，并用 RRF 形成混合召回；
4. 对每轮结果执行同一套约 50 条评测，记录增益、退化和新增 Bad Case。

## 6. 通过条件

- 评测集中的预期证据至少 10 条进入 Top-5；
- 每道有答案问题都通过事实、引用和额外说法检查；
- 无答案问题只在正确拒答且无引用时通过；
- 数字错误、否定反转、引用不匹配和未经核实的额外说法不得自动通过；
- 每轮对比都保留可复现配置和逐题结果。

## 7. 暂不实施

在基线生成前不调整生产 Embedding、不替换 Chunk 策略、不引入 Reranker，也不以单个 Bad Case 直接判断模型优劣。

## 8. 实施与验收记录

### 已完成的本地检索部分

- 首轮固定题集：`samples/acceptance/questions_v02_round1.json`，50 题；42 题有答案，8 题无答案。当前修订版及校验结果见第 9 节。
- 评测器：`scripts/evaluate_v02.py`，保存问题集和语料 SHA-256、脱敏后的模型配置、完整候选排名、逐题 Top-1/3/5 与汇总对照；索引只存在于单次评测进程内。
- 低耦合实现：BM25、RRF 与稠密检索使用独立 Retriever 实现和批量检索接口；答案事实/引用评估规则位于共享 `app/evaluation.py`，离线评测脚本通过接口组合这些实现。
- 函数说明：`app/`、`scripts/`、`tests/` 中 Python 函数均有中文 docstring，AST 审计结果为 0 个缺失。

### 首轮回答质量验收（2026-09-29）

用户明确授权将 3 份公开测试文档的检索片段与固定 50 题发送到 `.env` 配置的 DeepSeek Chat API 后，运行了 `scripts/evaluate_v02.py --quality`。结果为有答案题自动通过 24/42、无答案题正确拒答 6/8、待人工复核 12、执行错误 0；固定验收标准下**未通过**。Top-1/3/5 为 23/42、39/42、40/42，与本地基线一致。
