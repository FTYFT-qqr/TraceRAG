## 文档维护规则

1. 使用指南按主题维护操作步骤；版本总结只记录范围、最终状态及证据链接。
2. 新的规划或检查轮次单独建文件，采用 `三位编号_主题.md`，编号在版本内递增；V0.2 当前检查与整改为 `007`，下一轮从 `008` 开始。同一轮进展更新该轮文件，不把新轮次堆进总结。
3. 规划文件统一使用“范围与状态、现状与问题、修改要求、验收方式、结果与证据”五节。问题需给出可核对的行为或代码位置。
4. 每份 Markdown 仅用一个一级标题，正文从二级标题开始；列表、表格、代码块前后留空行，使用 UTF-8 编码、LF 换行及相对链接。
5. 自动运行写入新的评测目录，保留 JSON、测试 XML 和必要日志。历史结果标注日期、输入版本与执行范围；重评分、固定协议、真实模型质量分别说明。
6. 自动 Markdown 是 JSON 的阅读视图，最终两策略合为一份发布摘要；各轮原始结果通过证据索引查找。无 JSON 替代的 V0.1 报告保留。
7. 本次将重复导航、版本导读、分散整改和验收说明汇总为主题文档。逐题复核判断与原始证据保留；后续继续按独立编号记录新工作。
