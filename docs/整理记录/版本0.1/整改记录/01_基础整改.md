# TraceRAG V0.1 整改记录 001：基础整改

- 整理日期：2026-09-26。
- 类型：历史要求与实施记录，保留第 7.1–7.5 项的来源编号。
- 本记录只反映当轮已验收场景；当前拒答优先级的追加问题见 [整改规划 003](03_拒答评分与参考范围.md)。
- 版本范围及最新状态见 [V0.1 总览](../../../项目规划/版本0.1/版本规划.md)。

### 7.1 更新文档时移除旧内容

**现状：** 同名文件内容变化后会生成新的文档 ID，现有入库流程只追加新片段，旧片段仍可被检索，可能让回答引用过期内容。

**改动：** 将同名不同内容的上传视为更新。建立新索引快照时移除该文件旧版本的片段；保存成功后再切换当前快照。完全相同的文件重复上传仍应跳过。

- [x] 验收：先上传旧版，再上传同名新版，查询只会检索到新版内容；重载持久化快照后结果不变；重复上传相同内容不会增加片段。已由运行时回归测试覆盖。

### 7.2 收紧引用与拒答判断

**现状：** 生成内容只要包含一个有效的 `[n]` 编号，就可能被当作带证据的成功回答；编号存在不代表对应事实受到证据支持。

**改动：** 拒答语优先于引用编号，拒答时返回 `rejected=true` 且不返回引用。回答中的编号必须映射到本次检索结果；对有编号但事实不受证据支持的代表性问题，采用保守拒答或重新生成，并保留人工核对记录。不得把编号校验表述为通用事实核验。

- [x] 当轮验收：普通问题中的无证据、无效编号、带引用的固定拒答和自然语言拒答场景通过；正常引用可映射到来源。后续是否记载类问题的遗漏见独立规划 003。

### 7.3 防止混用不同 Embedding 模型的索引

**现状：** 索引快照只校验向量维度，没有记录生成向量所用的模型。同维度模型切换后复用索引目录，可能无提示地混用不同向量空间。

**改动：** 在索引元数据中记录 Embedding provider、模型标识或本地模型配置摘要以及向量维度。启动、入库和查询前核对当前配置；已知身份不匹配时明确提示使用新索引目录或重新建索引。缺少身份的旧快照不得默认兼容：启动时读取其中 Chunk 内容，用当前模型重新计算向量，保存 V2 快照后再切换当前版本，旧 generation 保留。

- [x] 验收：不同但同维度的模型访问已有索引时明确拒绝混用；无身份旧快照通过重新 Embedding 迁移，旧 generation 保留。对应向量库和运行时回归测试通过。

### 7.4 用真实问题完成第一版检索与拒答验收

**现状：** 现有 12 条检索测试使用人工构造的单位向量，只能证明排序代码工作，不能证明真实 Embedding 的召回率或默认拒答阈值适用。

**改动：** 用多份项目样本文档和当前选定的真实 Embedding/Chat 模型，准备至少 12 条人工编写的有答案问题及至少 3 条无答案问题，记录预期来源、Top-5 命中和拒答结果。保留基础测试；在可写临时目录的环境中跑完依赖 `tmp_path` 的用例，不将环境权限错误计为通过。

- [x] 验收：本轮 14/15 条有答案问题的预期证据进入 Top-5（超过至少 10 条的门槛），15/15 条有答案问题通过事实与引用质量核验，4/4 条无答案问题正确拒答；逐题记录见 [检索验收记录](../../../评测数据/版本0.1/验收记录/检索验收记录.md)，完整 80 项基础测试通过，见 [基础测试记录](../验收记录/基础测试记录.md)。此项是 V0.1 的最小验收，不替代 V0.2 的完整评测体系。

### 7.5 修正重复上传的界面提示

**现状：** API 标记文件已存在时，界面仍显示“加入 N 个片段”，容易让用户误以为重复入库。

**改动：** 根据 `already_indexed` 区分“已有索引，未新增片段”和首次入库的新增片段数；同名文件更新后显示替换完成的结果。

- [x] 验收：首次上传、完全重复上传、同名文件更新分别展示新增、未新增、替换提示；三种提示均有直接回归用例，并与 API/运行时状态一致。
