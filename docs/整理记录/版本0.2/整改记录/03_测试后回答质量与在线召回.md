# 03 测试后回答质量与在线召回整改

## 1. 测试依据

2026-10-03 用户完成测试后要求继续后续步骤。10月1日向量与BM25质量报告分别为18/43、20/43，正确拒答均7/7。逐题复核原始100个回答，并对48个未通过项记录判断，见[原始回答复核](../质量整改_2026-10-03/原始回答复核.md)。

本轮始终使用同一固定50题与三份公开样例。题集和语料未为提高分数而修改；历史原始报告与所有失败的中间运行均保留。真实Chat调用沿用用户对这批数据发送至已配置DeepSeek的明确授权。

## 2. 修复内容

| 问题 | 修复 | 回归依据 |
| --- | --- | --- |
| 同组等义表达误报引用不支持 | 来源可使用事实组内另一接受表达；仍限定到该句引用编号，剩余断言单独核验 | 下午时间表达、错误编号、附加无来源服务 |
| 自由改写导致评分不确定、引用格式缺失 | 模型只选择既有原文短句编号；代码从来源取出原文并逐句加引用 | 无效JSON、伪造编号、拒答混入引用、跨来源两项依据 |
| 原文复制协议失败 | 取消由模型复制文字，改为代码确定文本；复制协议失败结果保留 | 原文编号协议真实对照 |
| 分号前手续丢失 | 同一句内的分号保留在一个选择单元；展示时仍给每个分句引用 | 必填信息与收到确认同选，不截断数值和否定 |
| 无关来源的相似规定混入 | 提示要求选择覆盖所问主题的文档；固定题集检查引用文件是否属于声明的预期来源 | 实验室回答混入图书馆条款必须失败 |
| 漏召回使可回答问题拒答 | 接入可配置vector、bm25、hybrid在线召回；上传更新后重建稀疏表 | 同名替换、重启恢复、原始通道门槛 |
| 融合分被当作相关度 | API返回score_kind及两路原始分；界面区分余弦、BM25与RRF排序分 | 接口字段和策略拒答测试 |
| 相同提示下实现变化不可区分 | 新报告保存原文选择协议和关键实现文件SHA-256 | 最终报告可复现配置 |

代码职责分开：`grounded_answer.py`负责短句准备与输出校验，`chat.py`负责请求与选择约束，`evaluation.py`负责固定题集的事实/引用验收，`runtime.py`负责按配置组合检索器。新增函数均有中文说明。

## 3. 完整性专项

- `LAB-V2-07`：回答必须包含未列出的费用/赔偿对象及等待管理员书面答复，不能拼入图书馆规定。
- `CLINIC-V2-10`：必须引用采样时间以当天叫号屏和工作人员说明为准，不能因向量漏召回而直接拒答。
- `CLINIC-V2-11`：旧标注允许仅说“与年度体检报告相同”。本轮保持题集不变，额外核对答案给出“一楼登记台”及间接地点、具体地点两项原文依据。
- `LAB-V2-02`：预约提前量、填写信息和柜台确认须完整提供；分号保留解决选择单元造成的漏答。

## 4. 在线配置

`TRACERAG_RETRIEVAL_STRATEGY`支持`vector`、`bm25`、`hybrid`，缺省为`vector`以兼容原配置。混合召回不改变Embedding身份，也不要求重新上传文档；BM25表从已有Chunk文本建立，重启和同名文档更新均会刷新。

`TRACERAG_BM25_MIN_SCORE=0`为原始分严格大于0的生成预筛选；`TRACERAG_RRF_K=60`控制融合排序。余弦门槛独立配置；所有策略仍须生成证据支持的回答，不能凭任一路分数证明可回答。

最终验收已通过，本地已启用混合召回并启动API及界面。回退为`TRACERAG_RETRIEVAL_STRATEGY=vector`并重启API，已有向量快照无需重建。

## 5. 结果与范围

最终两组均43/43质量通过、7/7正确拒答，复核与错误均0，209项本地回归通过，288个函数中文说明缺失0个。详见[本轮验收结论](../质量整改_2026-10-03/验收结论.md)。本地已启用混合召回；V0.2本轮实现达到冻结条件，工程发布后续进行。

原文选择协议的回答采用来源原语言，暂不提供自由改写或翻译。格式错误会明确报错，不返回未经校验的回答。原文存在只能证明文本来源，不能自动证明选择的主题、条件和覆盖范围完整，因此固定评测和实际业务验收仍必要。扫描PDF的OCR等既有范围限制不变。
