# TraceRAG 容器部署

- 适用范围：Docker API/UI、本地模型与索引持久化
- 整理日期：2026-10-04

## 启动 API 和 UI

需要 Docker Engine 与 Compose v2，容器使用 Python 3.13 和 CPU FAISS。项目端口默认为 API `18000`、UI `18501`，以便与当前本地服务并存。

在项目根目录执行：

```powershell
Copy-Item .env.docker.example .env.docker
# 编辑 .env.docker，填写已选服务的 API Key、地址及模型名。

docker compose up -d --build --wait
```

访问 <http://127.0.0.1:18501/>，API 健康检查为 <http://127.0.0.1:18000/health>。UI 的侧栏默认使用容器网络地址 `http://api:8000`；请求由 UI 服务发出。

Compose 等待 API 健康检查后启动 UI；宿主机端口只绑定 `127.0.0.1`。机制见 [Docker 启动顺序](https://docs.docker.com/compose/how-tos/startup-order/) 和 [端口发布说明](https://docs.docker.com/engine/network/port-publishing/)。

## 使用已下载的本地 BGE-M3

本地权重不复制进镜像。以下以模型目录 `D:/rag/embedding` 为例，部署时替换为实际路径并只读挂载：

```powershell
$env:TRACERAG_MODEL_DIR = 'D:/rag/embedding'
docker compose -f compose.yaml -f compose.local.yaml up -d --build --wait
```

本地方案额外安装 CPU 版 PyTorch 和 Sentence Transformers，构建时间和镜像大小高于在线 Embedding 方案。API 容器读取 `/models/embedding`，使用 CPU；权重目录必须真实存在，否则挂载失败。

`.env.docker` 中保留 Chat API Key、地址和模型名；例如已有 DeepSeek 服务时将地址设为 `https://api.deepseek.com`，模型名填写当前账号实际可用的型号。本地向量无需 Embedding API，但回答仍需 Chat 服务。

本机旧索引中的模型身份含 Windows 路径，容器使用 Linux 路径。容器使用独立索引卷，首次应重新上传资料；不要直接复用 Windows 旧向量目录。

## 配置与持久化

| 内容 | 位置或配置 |
| --- | --- |
| 凭据 | `.env.docker`，Git 与构建上下文均排除 |
| 在线模型 | `TRACERAG_BASE_URL`、`TRACERAG_CHAT_MODEL`、`TRACERAG_EMBEDDING_MODEL` |
| 检索策略 | `vector`、`bm25`、`hybrid`；容器示例默认 hybrid |
| 索引 | 命名卷 `tracerag-index`，API 内 `/var/lib/tracerag/indexes` |
| 本地权重 | 只读挂载到 `/models/embedding` |
| 宿主机代理 | `TRACERAG_API_PROXY_URL=http://host.docker.internal:7897` 等实际地址 |
| 端口 | 设置 `TRACERAG_DOCKER_API_PORT`、`TRACERAG_DOCKER_UI_PORT` 后再启动 |

不要把 Windows 的 `.env` 直接作为容器配置，也不要在容器代理地址中使用宿主机的 `127.0.0.1`。Linux Docker Engine 使用宿主代理时需额外配置实际可访问的宿主地址。

```powershell
docker compose ps
docker compose logs --tail 100 api ui
docker compose restart api
docker compose down
```

普通 `down` 保留索引卷。删除卷会删除容器知识库，维护时应先备份；日常重启无需删除卷。

## 容器工程验收

无需真实密钥的固定协议验收：

```powershell
docker build -t tracerag:0.2.0 .
docker run --rm tracerag:0.2.0 python scripts/delivery_smoke.py --output-dir /tmp/工程验收
```

该脚本检查真实 API/UI、上传、重复跳过、同名替换、回答引用、拒答与进程重启恢复。模型响应来自本地固定协议服务，不能据此宣称真实模型回答质量通过。

真实模型与跨容器重启验收按[演示指南](演示指南.md)进行。当前环境的实际执行状态见[工程交付验收](../版本记录/V0.2/004_工程交付验收.md)。

本地模型 Compose 已启动后，可以自动执行三份公开资料和五个定向质量场景，再重启 API 容器验证索引卷恢复：

```powershell
python scripts/container_acceptance.py --compose-project tracerag --output-dir data/容器验收_新目录
```

`--compose-project` 必须与启动时的 Compose 项目名一致；输出目录必须尚不存在。脚本检查回答事实、预期文件来源、引用 Chunk、否定事实及拒答，重启后先查询再重复上传。它不会修改本机旧索引，五个场景也不替代完整 50 题质量评测。

本机安装位置、资源限制及实测结果属于环境记录，见[工程交付验收](../版本记录/V0.2/004_工程交付验收.md#docker-实测与本机迁移)。
